2. **任务定义与挑战分析**
   
   这一节对应评分点“研究内容、任务中的挑战有清晰描述”。

   建议写：
   - 输入：`numbers = [a,b,c,d]`，目标 `target=24`；
   - 输出：`<think>...</think><answer>expression</answer>`；
   - 合法性约束：数字必须且只能使用一次，表达式只允许四则运算和括号，结果等于目标值；
   - 不可解样本：应输出 `NO_SOLUTION`，不能乱编表达式。

   挑战建议分成 5 点：
   - **组合搜索空间大**：括号结构、数字排列、运算符组合都需要搜索；
   - **奖励稀疏**：只有完整表达式正确才有准确率奖励；
   - **格式与语义双重约束**：模型既要输出 R1 风格格式，又要表达式正确；
   - **幻觉风险**：不可解样本上模型容易强行编造答案；
   - **RL 训练不稳定**：GRPO 可能提升候选质量，也可能增加 greedy hallucination。

3. **问题建模与创新设计**
   
   这一节专门承接“创新点，针对问题本身有进一步分析与建模”。

   建议把创新点明确写成 4 个小节：

   3.1 **Target-aware 统一建模**
   
   将任务统一表示为：

   ```text
   (numbers, target) -> expression
   ```

   24 点是 `target=24` 的特例，Countdown 是任意 target 的扩展。

   3.2 **Verifier-based RLVR 建模**
   
   把奖励函数建立在严格程序验证器上，而不是人工标注或奖励模型。

   3.3 **不可解样本的 hallucination 建模**
   
   不只评估可解题准确率，还评估模型在不可解题上是否乱编。

   3.4 **Verifier-based test-time compute**
   
   将模型建模为候选表达式生成器，采样 `N` 个候选，再用 verifier 筛选正确表达式。这是目前最强亮点。
